# Context Playbooks

## Landing Pages

- Lead with a specific promise, not generic hype.
- Make the primary CTA visible above the fold.
- Use sections as a story: problem, value, proof, details, action.
- Avoid interchangeable feature cards; each section should earn its place.

## Dashboards

- Start with decision hierarchy: what needs attention now?
- Separate monitoring, analysis, and action surfaces.
- Use color for status and exceptions, not decoration.
- Provide empty, loading, stale-data, and error states for data widgets.
- Keep charts readable: labels, units, legends, and accessible color choices.

## Forms

- Keep labels visible; placeholders are not labels.
- Group related fields and show progress for long flows.
- Validate at useful moments; do not punish users while typing.
- Errors should say what happened and how to fix it.
- Make submit, cancel, and destructive actions visually distinct.

## Components

- Define anatomy: container, content, actions, states, variants.
- Keep variants meaningful; avoid props that create arbitrary visual combinations.
- Include keyboard, focus, disabled, loading, and error behavior.
- Components should fit the system, not become isolated art pieces.

## Charts and Data Viz

- Choose chart type by question: compare, trend, distribution, relationship, part-to-whole.
- Label axes and units; avoid mystery numbers.
- Use annotations for important thresholds or anomalies.
- Do not use 3D, excessive gradients, or color-only distinctions.

## Mobile

- Prioritize thumb-friendly actions and readable density.
- Avoid desktop-first tables; use cards, summaries, or drill-down patterns.
- Account for safe areas, keyboard overlays, and slow networks.
- Hover-only interactions must have touch equivalents.
