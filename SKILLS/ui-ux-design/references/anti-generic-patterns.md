# Anti-Generic Patterns

## Red Flags

- Purple/blue gradient hero with centered text and three cards, with no product-specific reason.
- Inter/Roboto/Arial by default when no design-system constraint exists.
- Same rounded white cards, same icons, same shadows, same layout for every project.
- Glassmorphism that hurts contrast or exists only because it looks “modern”.
- “Premium” styling that adds blur, noise, glow, and animation without improving the task.
- Dashboards where all metrics have equal visual priority.
- Forms that look clean but hide labels, errors, help text, or focus order.
- Components with no loading, empty, disabled, or error state.
- Mobile layouts that are just squeezed desktop screens.

## Correction Moves

- Replace generic decoration with product-specific visual language.
- Introduce one memorable constraint: editorial typography, strong grid, distinctive accent, custom illustration, data-first layout, or brand-driven motif.
- Use semantic tokens instead of one-off colors.
- Make spacing rhythm consistent before adding more visual effects.
- Reduce competing accents; make one thing dominant.
- Add state design before polishing static screenshots.
- Prefer clarity over novelty in critical flows: login, payment, forms, destructive actions.

## Respect Existing Systems

If the product already has a design system, do not fight it. Improve within its tokens, components, and accessibility rules. Distinctiveness comes from composition, hierarchy, content, and interaction quality—not random visual rebellion.
